# 登录失效自动跳转修复报告

> 版本：v1.0 | 日期：2026-08-06 | 状态：已完成

## 用户需求

登录会话失效后，前端应自动清理失效会话并跳转到登录页。

## 结论与证据

- 后端 `GlobalExceptionHandler` 对鉴权失败返回 HTTP 401。
- 前端路由守卫只在路由切换时检查本地令牌；页面停留期间发生 401 不会触发守卫。
- 原 Axios 响应拦截器仅原样拒绝错误，没有清理会话或导航，因此失效令牌持续保留。
- 修复前回归测试稳定失败，表现为收到 401 后 `supervision_token` 仍存在。

## 完成的修改

- 在前端统一响应拦截器中处理 HTTP 401。
- 删除本地令牌和用户信息，并使用页面替换导航到 `/login`。
- 登录页不重复导航；并发 401 只触发一次跳转。
- 保留原始错误拒绝行为，避免改变现有调用方的错误处理语义。
- 新增请求层回归测试和 `npm test` 脚本。

## 影响模块

- `build/web/src/api/index.ts`
- `build/web/src/api/index.test.ts`
- 前端测试依赖与锁文件

## 验证结果

- 定向回归测试：1 个测试通过。
- 前端生产构建：通过。
- 构建仍有既有的大包体提示，不影响本次功能。

## 风险与后续

当前行为会在 401 时执行整页替换，可确保内存态与失效会话一起清空。后续若需要保留用户原访问地址，可在登录跳转中增加受控的回跳参数。
